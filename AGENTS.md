## GLOSSARY (canonical terms — never synonymize)

- **plan** — versioned JSON declaring an edit; the only input to render.
- **observation** — timestamped JSON emitted by a worker; never rendered, never mutates source.
- **worker** — deterministic analysis producing an observation (detect-silence, detect-scenes, transcribe, detect-filler).
- **bridge** — deterministic observation→plan expansion (`plan --cuts-from`).
- **timeline op** — `trim`/`cut`: absolute source-time ranges; order-independent; trims union, cuts subtract.
- **transform op** — `speed`/`resize`/`volume`/`normalize-audio`/`audio-mix`/`overlay-text`/`image-overlay`/`zoom`: global, ≤ 1 each per plan.
- **transition op** — `crossfade`: TIMELINE-affecting global op (≤ 1 per plan) that joins the compiled keep-segments with fade transitions instead of hard cuts; shortens the output by (N−1)·duration; never combined with `audio-mix`.
- **export op** — `export-gif`: TERMINAL op (last position only, ≤ 1 per plan; the only order constraint in an otherwise order-independent plan) that changes the output FORMAT, not the content — first of an export-op class; never a `TransformOpType` member.
- **engine** — swappable transcription backend behind one interface (`src/analysis/transcribe/engines.ts`).
- **preview** — cheap render to `<output>.preview.mp4` (640 w, ultrafast, CRF 30); under an `export-gif` op it is instead a real `<output>.preview.gif` (the op's own width/fps bound the cost); can never touch the final path.
- **source-id** — cache key = sha1(absPath|size|mtimeMs); changed file ⇒ new id, no invalidation logic.

## WORKFLOWS (proven sequences; steps are the contract)

- **W1 basic edit**: `inspect` → `plan > plan.json` → edit `operations` → `validate` until valid → `preview` → iterate → `render` once.
- **W2 tighten silence**: `detect-silence > silence.json` → `plan --cuts-from silence.json > plan.json` (tune `--min-duration`/`--pad` = the editorial decisions) → prune cuts by judgment → W1 tail.
- **W3 speech review**: `transcribe > transcript.json` → `detect-filler transcript.json > filler.json` → `plan <input> --cuts-from filler.json --filler-pad-before 0.10 --filler-pad-end 0.25 > plan.json` (tune the pads = the editorial decisions) → prune cuts by judgment → W1 tail. Filler times are exact word anchors when the transcript carries word timings (`params.precision: "words"` — whisper-cpp `--word-timestamps`); linear estimates within segment granularity otherwise (`"segments"` — verify with `extract-frame --at` before rendering).
- **W4 strategy**: `diagnose` → `benchmark` → pass `--encoder` to render accordingly. For audio loudness: `measure-loudness` → pick `normalize-audio.target` (or compute the `volume` gain = target − `inputI` dB) with the measurement as evidence → W1 tail.
- **W5 MCP**: `video mcp` (stdio; or bin `video-mcp`) or `video mcp-serve` (streamable HTTP — `http://127.0.0.1:8765/mcp`, flags `--port/--host/--token`; token REQUIRED for a non-loopback `--host`); tools = `video_<command_snake_case>`; results identical to CLI stdout; failures = `isError:true` + `{error:{code,message,details}}`. HTTP client config (ZCode-style): `{"type":"http","url":"http://127.0.0.1:8765/mcp","headers":{"Authorization":"Bearer …"},"timeoutMs":…}` — set a generous `timeoutMs` for renders: no SSE push exists, so long renders depend on the client's own request timeout (the same blackout as stdio).
- **W6 highlight compilation**: `transcribe > transcript.json` → `find-highlights <input> --transcript transcript.json > highlights.json` → `plan <input> --highlights-from highlights.json > plan.json` (tune `--count`/`--min-score`/`--pad` = the editorial decisions) → prune trims by judgment → W1 tail. Deterministic bridge per GLOSSARY; the agent decides.
- **W7 scene review**: `detect-scenes > scenes.json` → `review-frames <input> --scenes scenes.json > review.json` (tune `--per-boundary`/`--window` = the editorial decisions) → inspect the grouped jpgs → express judgments as `trim`/`cut` ops → W1 tail. Still groups, not a proxy, are the review unit.

| `export-gif` | `width?` (px, int 1–16384, default 480 — vedit's proven value) · `fps?` (> 0, ≤ 60, default 12) · `from?`/`to?` (s, OUTPUT-timeline sub-range; both absent = the whole output) | TERMINAL export op (first of the export-op class): renders the compiled OUTPUT timeline (post trim/cut, crossfade-adjusted, post-speed) to an animated GIF in the SAME single invocation — the palette is generated INSIDE the one `-filter_complex` via `split` (recipe proven in vedit's build_gif, vedit.py:363-375): the from/to window as an output-timeline `trim` BEFORE `fps`, then `fps=N,scale=W:-2:flags=lanczos,split[a][b];[a]palettegen=stats_mode=diff[p];[b][p]paletteuse=dither=bayer:bayer_scale=5` appended AFTER the composed video chain (select or xfade chain → zoom/scale/subtitles/overlay; `-2` height keeps aspect, even). bayer dither is ordered/deterministic. The classic two-pass palette workflow is NEVER used (would break INVARIANT 1). GIF carries no audio: audio is dropped by design — an audio-bearing source emits a `GIF_AUDIO_DROPPED` validate WARNING (not an error); `volume`/`normalize-audio` under export-gif are no-ops (audio plumbing never built); `export-gif` + `audio-mix` → `OPERATION_INVALID` (the bed would be a silently dropped no-op — the crossfade+audio-mix fence precedent). Bounds: LAST operation (`OPERATION_INVALID` otherwise — the plan's only order constraint); ≤ 1 per plan; `from < to` else `RANGE_NEGATIVE`; `from`/`to` ≤ expected output duration ((timeline − crossfade shrinkage)/speed — the same canonical expectation overlay-text consumes) else `OPERATION_INVALID`; `output.path` MUST end `.gif` (case-insensitive) else `OUTPUT_PATH_INVALID`, enforced in validate AND the builder. Preview renders a real `<output>.preview.gif` (INVARIANT 2 holds; the op's own width/fps bound the preview cost — the mp4 preview's 640w is not applied; a `resize` op still composes before the gif scale). `--encoder` ignored (gif muxer; `RenderResult.encoder` = `gif`). h264 flags/movflags omitted on the gif branch. Practical note: gif wall-time/size grow with window length — use `from`/`to` for loops |

Rules: ops order-independent (EXCEPTION: `export-gif` is terminal — last position only) · ≤1 of each transform, ≤1 `crossfade`, ≤1 export op · renders are ONE ffmpeg pass (select-based multi-range, or the crossfade transition chain when a `crossfade` op is present with ≥2 segments; an `export-gif` appends the palette graph inside the SAME pass) · preview path ≠ final path · `--force` required to overwrite explicit outputs · source can never be an output.

Zod source of truth: `src/core/schemas.ts`. Shapes: SilenceReport `{segments:[{start,end,duration}], duration?, note?, params?}` · SceneReport `{boundaries:[{timestamp,confidence}]…}` · TranscriptReport `{segments:[{start,end,text,words?:[{start,end,text}]}], engine?, model?, language?, params?}` (`words` present only from whisper-cpp `--word-timestamps` — absence means segment granularity only; `params.wordTimestamps` records the flag on the native path; windowed params carry `chunkSeconds`/`snapToSilence` instead) · FillerReport `{instances:[{start,end,phrase,context}], params?{phrases, precision}}` (`precision: "words"` = exact anchors from `segments[].words`, `"segments"` = linear interpolation; `"words"` only when every segment carries words; phrases never match across segments) · HighlightReport `{candidates:[{start,end,score,text,reasons[]}], params?}` (score = weighted speech-rate 0.45 / pause-before 0.2 / keyword 0.25 / length-band 0.1, renormalized when keywords unset; deterministic proposal — the agent decides) · LoudnessReport `{inputI?, inputTP?, inputLRA?, inputThresh?, duration?, note?, params?{targetI}}` (loudnorm first pass; values exactly as loudnorm emits them — LUFS/dBTP/LU, not rounded; all four measurement fields are ABSENT when there is nothing to measure: audio-less source or digital silence (loudnorm `-inf`) return `{duration, note}`).

## ENGINES (transcription)

- **handy** (implemented; priority 1 — the default): binary `/Applications/Handy.app/Contents/MacOS/handy` (or `~/Applications/…`). Headless: `-f <16kHz-mono.wav> --json [--model <id>]`. stdout = single JSON `{text, model, best_ms, audio_secs, rtf,…}`; logs → stderr; **exits in `-f` mode; `--list-models` mode never exits — always wrap with timeout**. Default model on this machine: `parakeet-tdt-0.6b-v3` (Q8_0, Metal; 5–21× realtime measured).
- **whisper-cpp** (implemented; priority 2): binary `whisper-cli` on PATH (whisper-cpp 1.9.2, ggml 0.22.0 BLAS + Metal, flash-attn on). Native segments: `whisper-cli -m <resolved-model> -f <16kHz-mono.wav> -ojf -of <tmp-prefix>` writes exactly ONE file `<tmp-prefix>.json`; stdout = human segment lines, stderr = ggml/Metal logs (both ignored — the JSON file is the only channel); NO `-l`/`-wt`/`-ml`/`-sow`/`-dtw`/`-nfa` flags (measured harmful or no-ops — R2 candidate table, docs/ultron/research/r2-whisper-word-timestamps.md). Parse contract: `transcription[].{offsets{from,to} MS, text, tokens[]}`; words = leading-space tokens (skip `[_*` specials; punctuation/BPE tails append and extend end; zero-width `end:=next.from` in-segment, else left zero — never invented); ms÷1000 at 3 decimals. Exit 0 ok; any non-zero → `TRANSCRIPTION_ENGINE_FAILED` with stderr tail (availability is probed before spawn). Timeout `60 s + 2×duration` (≥11× headroom over worst measured RTF 0.177); RTF 0.06–0.10 warm (10–16× realtime) for `ggml-base.en.bin`. Models (ordered; R2's table EXTENDED with a second location — showcase defect fix, cwd-only resolution failed from any non-repo cwd): explicit resolvable `--model` path > `.video-agent/models/<name>` in the cwd > the same name under the toolkit root's `.video-agent/models/` (root derived from the module's own location, not the cwd) > default `ggml-base.en.bin` at the same two locations > `TRANSCRIPTION_ENGINE_UNAVAILABLE` with `details.known` sorted `*.bin` listing of BOTH models dirs (paths prefixed by their dir; whisper-cli does NO name magic and NO download — the engine always passes an explicit `-m`); `detect()` = binary on PATH AND default model resolvable (either location), detail names both facts.
- **Windowing split** (the orchestrator honors the capability): engines WITHOUT `transcribeSegments` (handy) are windowed by the toolkit (chunk default 25 s, boundaries snapped to silence gaps ±chunk/3, exact times by construction; 1 h source ≈ minutes; cached per source+engine+model+chunk). Engines WITH `transcribeSegments` (whisper-cpp) run UNWINDOWED — ONE whole-file 16 kHz mono WAV invocation, native segments + optional words; `--chunk`/`--no-snap`/`--concurrency` are no-ops (R2 measured windowing as pure overhead: 15.7–16.2× realtime unwindowed on 55.75 s).
- **Parallel windows** (safe + deterministic): `--concurrency <n>` runs per-window WAV extraction + engine invocations as bounded parallel jobs — engine invocations are independent processes (each loads its own model; keep n conservative on 16 GB; tmp WAVs unique per window index). Results are reassembled in window order, so out-of-order completion cannot reorder segments; the lowest-index window failure fails the whole task; report byte-identical to sequential (measured 1.8× wall-time at n=2 vs 4.95 s sequential on a 26 s source, 2026-09-03). Default n = cached `video benchmark` renderConcurrency for the source when an integer in 1..4, else 1.

## INVARIANTS (violating these is a bug)

1. One ffmpeg pass per render — no intermediate encodes.
2. Source is never written; explicit outputs need `--force`; preview never writes the final path.
3. Workers never render; render never reads observations (plans are the only bridge).
4. All timestamps: seconds, float, emitted at 3 decimals.
5. Child processes: argv arrays only; engines wrapped with timeout.
